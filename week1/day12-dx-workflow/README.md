# Day 12 - DX Workflow

# What is Salesforce DX?

Salesforce DX (Developer Experience) is a set of tools that helps developers build, test, and manage Salesforce applications more efficiently.

It provides a modern development approach using source-driven development, command-line tools, and version control systems.

### My Understanding

As a beginner, I understood that Salesforce DX helps developers organize their work and develop Salesforce projects more easily.

---

# Why CLI Matters

CLI stands for Command Line Interface.

It allows developers to interact with Salesforce using commands instead of clicking through many screens.

CLI helps to:
- Create projects
- Deploy code
- Retrieve metadata
- Run tests
- Manage Salesforce orgs

### My Understanding

CLI makes development faster because many tasks can be completed using simple commands.

---

# Why GitHub Matters

GitHub is used to store and manage project code.

It helps developers:
- Save project versions
- Track changes
- Work with teams
- Recover previous versions

### My Understanding

GitHub acts like a backup and collaboration platform where developers can safely manage their work.

---

# Team Collaboration Problems

When multiple developers work on the same project, some challenges can occur:

- Code conflicts
- Duplicate work
- Accidental changes
- Difficulty tracking updates
- Communication issues

### Example

Two developers modify the same file at the same time. This can create merge conflicts that must be resolved.

# Enterprise Workflow Discussion

A typical Salesforce enterprise workflow looks like this:

```text
Requirement Gathering
         |
         v
System Design
         |
         v
Development
(Apex, Flows, LWC)
         |
         v
Testing
         |
         v
GitHub Version Control
         |
         v
Deployment
         |
         v
Production Use
```

### My Understanding

Enterprise projects follow a structured workflow so that development is organized, tested, and properly managed before users access the system.
